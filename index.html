The problem

Your AI agents can run commands, access credentials, exfiltrate data, and install plugins. Your security team has zero visibility.

Enterprises face a binary choice: deploy AI agents with full access and accept the risk, or restrict them so heavily they can't deliver value. Neither option works when you're responsible for compliance, data protection, and incident response.

The solution

Snapper eliminates the tradeoff. Agents keep full capability. Your security team gets full visibility, real-time threat detection, and human-in-the-loop control.

Snapper hooks into the agent's tool pipeline and evaluates every action against configurable rules before it executes. Heuristic bad actor detection identifies multi-step attack patterns. Kill chain state machines catch data exfiltration, credential theft, and privilege escalation in real time. Sensitive operations route to Telegram or Slack for human approval. PII lives in an AES-256-GCM encrypted vault the agent never touches. CEF/Syslog events flow to your SIEM. The result: full agent power with enterprise-grade governance.

Security Feed Auto-Mitigation

Snapper continuously monitors three security intelligence feeds and automatically creates mitigation rules when new vulnerabilities affect your agents' tools. The NVD (National Vulnerability Database) provides CVE data from NIST. The GitHub Advisory Database covers open-source package vulnerabilities. ClawHub — Snapper's own feed at api.clawhub.io — delivers agent-specific threat intelligence. When a new CVE matches an active agent tool, Snapper auto-generates deny or approval rules before the vulnerability can be exploited.

NVD/NIST · GitHub Advisories · ClawHub agent intel · auto-generated deny/approval rules

How it works

Snapper is a security product — so we hold ourselves to the same standard we enforce on agents.

Fail-Closed by Default

Every evaluation path defaults to deny. No rules configured? Deny. Rule engine error? Deny. Network timeout? Deny. This is non-negotiable — your agents never operate without policy enforcement.

Encryption at Rest

PII vault uses AES-256-GCM with HKDF-derived keys. Vault tokens are 128-bit random with domain locking and 30-second TTL. Zero plaintext PII is stored anywhere in the system.
