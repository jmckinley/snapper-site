Getting Started

Quick Start

Register, create an agent, install the hook, add your first rule, and test — in under 5 minutes.

  1. Create your account at app.snapperprotect.com
  2. Register an agent and save the API key returned in the response
  3. Install the Snapper hook in your IDE or agent environment
  4. Create your first rule (COMMAND_ALLOW for safe read commands)
  5. Test with the evaluate endpoint or Telegram/Slack bot commands

Core Features

Rules & Policies

26 rule types including command allow/deny, rate limiting, PII gates, time restrictions, human-in-the-loop approval, MCP tool allowlists/denylists, cost limits, multi-agent chain-of-custody, data classification, and geolocation restriction. Rules evaluate in priority order; DENY always short-circuits.

COMMAND_ALLOW COMMAND_DENY RATE_LIMIT PII_GATE HUMAN_IN_LOOP CREDENTIAL_BLOCK DENYLIST TIME_RESTRICTION TOOL_ALLOWLIST TOOL_DENYLIST OUTPUT_SIZE_LIMIT DEPENDENCY_CONTROL COST_LIMIT CHAIN_OF_CUSTODY DATA_CLASSIFICATION GEOLOCATION_RESTRICTION

PII Vault

AES-256-GCM encrypted storage for secrets. Agents see vault tokens ({{SNAPPER_VAULT:...}}), never real values. Two modes: protected (requires approval) and auto (resolves immediately).

{{SNAPPER_VAULT:<32-hex>}}

HKDF key derivation, brute-force lockout (5 failures / 15 min), 30-second TTL, one-read expiry, domain-locked tokens.

Approvals

Human-in-the-loop workflow via Telegram, Slack, or API. When a rule returns REQUIRE_APPROVAL, the agent pauses until a human approves or denies.

Allow Once — one-time approval for this specific request.
Allow Always — creates a persistent ALLOW rule for matching requests.

Alert routing: numeric owner_chat_id sends to Telegram, U-prefix sends to Slack DM.

Security

Trust Scoring

Two-layer trust model. Behavioral trust (0.5–2.0 multiplier) adjusts rate limits based on per-agent behavior — only rate-limit breaches penalize it. Composite trust (0–100 score) aggregates signals from 8 SIEM sources (Proofpoint, CrowdStrike, SentinelOne, Okta, Splunk, Darktrace, Microsoft Sentinel, Palo Alto) — scores below 20 force REQUIRE_APPROVAL on all actions. Intent drift penalties (0–15%) apply when an agent's command patterns diverge from established intent baselines.

Behavioral: 0.5x–2.0x · Composite: 0–100 · 8 SIEM sources · Intent drift: 0–15% penalty

Threat Detection

Real-time behavioral analysis: 13 signal types, 7 kill chain patterns (data exfil, credential theft, PII harvest, encoded exfil, privilege escalation, vault extraction, LOTL), behavioral baselines with 7-day rolling window. Feed health monitoring with auto-recovery and air-gapped threat intel support. Built-in Red Team Simulator admin dashboard with 35 attack scenarios (29 general + 6 MCP-specific) for validating detection rules and kill chain coverage.

Score ≥60 → approval required · ≥80 → auto-deny · Feed health: 15-min checks · Red Team: 35 scenarios

Plugin Integrity

Canary probes detect plugin removal/disabling (heartbeat every 5 min, alert on 3 misses). Evaluation receipts detect selective bypass (single-use UUID on every allow, verifiable by downstream proxies via X-Snapper-Receipt).

Canary: 5-min heartbeat · Receipts: 60s TTL, single-use

Emergency Controls

Instant kill switch. /block stops ALL agents immediately via Telegram, Slack, or API. Creates priority-1000 DENY rules across all rule types. /unblock resumes normal operations.

Priority 1000 · all agents · all rule types · instant

Behavioral Baseline Monitoring

Snapper learns each agent's normal behavior using 7 metrics (request rate, deny rate, token usage, commands, errors, PII rate, approvals) and alerts when an agent deviates from its baseline. Uses exponential moving averages with z-score anomaly detection.

  • 7-metric EMA per agent (24h bootstrap, then live alerts)
  • Warning threshold (score ≥60) and Critical threshold (score ≥80 → force approval)
  • Per-agent Baseline tab in the agent detail view
  • Org-wide anomaly feed: GET /api/v1/baseline/anomalies

Advanced Intent Analysis

Multi-layer analysis of what an agent is actually trying to do, beyond pattern matching. Prompt injection ML (DeBERTa classifier) detects manipulation attempts with confidence scoring. Intent drift detection measures Shannon entropy of each agent's command history — deviations from established intent baselines trigger trust penalties and alerts. AI Arbiter (8 async roles) provides post-decision review, approval triage, false-positive learning, conspiracy detection, and compliance gap analysis using tiered model routing.

  • DeBERTa classifier: 50+ regex patterns + ML scoring
  • Intent entropy tracked per agent (circular buffer, 100 entries)
  • Intent drift penalty: 0–15% trust reduction
  • AI Arbiter: 8 roles, no hot-path impact, local/Haiku/Sonnet routing
ML: DeBERTa · Intent: Shannon entropy · Arbiter: 8 async roles · Tiered model routing

Kernel Sandbox (Snapper Cage)

OS-level mandatory access control applied at agent launch — not per-request. Phase 1 (shipped): Landlock LSM (Linux 5.13+) and Seatbelt (macOS) enforce filesystem, process, and network restrictions. Profile auto-derived from 26 rule types; no root required. Phase 2 (eBPF Sentinel): Ring-buffer syscall/network/process event monitoring with behavioral DNA, Q-Learning escape detection, and cross-layer signal correlation. Cage fails safe — a caging failure leaves the agent running uncaged rather than crashing.

  • Landlock ABI v1–v5 (kernel 5.13–6.7+), Seatbelt on macOS 12+
  • Circuit breaker: 3 failures → cage bypassed, agent continues
  • Hot path: zero kernel calls during evaluate (<2ms overhead)
  • Admin dashboard at /admin/cage
Landlock · Seatbelt · eBPF Sentinel · Profile auto-derived · No root needed

Network Enforcement

Snapper enforces at three layers: SDK hooks (voluntary), network proxy (mandatory), and code scanner (pre-deployment). Together they ensure no AI traffic escapes governance.

Network Proxy

Transparent HTTPS proxy (Go binary, <15MB) that intercepts AI API traffic at the network layer. Monitors 55+ AI provider domains. Two modes: SNI (zero-config, domain-level) and MITM (full request inspection with canary token injection). Circuit breaker, Prometheus metrics, SIEM integration, fail-open/closed, config sync from Snapper API.

55+ AI domains SNI mode MITM mode SANITIZE INTERRUPT FINGERPRINT BASELINE Canary tokens Prometheus Circuit breaker

Detection Capabilities

Active Prevention: Tool result sanitization (SANITIZE, CEF-915) strips injection attempts from LLM responses before they reach the agent. Kill chain circuit breaker (INTERRUPT, CEF-916) blocks compromised agents for a configurable window (default 1 hour) the moment a multi-step attack is detected.

Behavioral Analytics: Model fingerprinting (FINGERPRINT, CEF-917) catches model bait-and-switch attacks via statistical drift detection using Welford's algorithm. Per-agent baselines (BASELINE, CEF-918) detect traffic anomalies — new domains, request size spikes, and token volume spikes — using EMA tracking.

All four capabilities ship enabled by default and are configurable live via Settings → Proxy Detection Settings or the GET/POST /api/v1/proxy/detection-settings API.

Multiple Proxy Instances

Run as many proxy instances as needed against a single Snapper control plane — no manual configuration required. Each instance self-registers on startup and appears in the proxy node registry within 30 seconds. Instances that stop sending heartbeats are automatically removed within 90 seconds.

Rule propagation: Rule changes reach all running proxy instances within ~10 seconds. Each proxy polls for cache invalidation events on a 10-second interval.

Verify running instances:

terminal
curl -H "X-API-Key: $SNAPPER_API_KEY" \ https://app.snapperprotect.com/api/v1/proxy/nodes

Supported deployment patterns:

  • Active/active HA pair — Two proxies behind a load balancer to eliminate single-proxy SPOF
  • Per-network-segment — One proxy per subnet or VLAN for network-level enforcement at each boundary
  • Kubernetes DaemonSet — One proxy pod per node; agents connect to the node-local proxy

Code Scanner

CI/CD scanner (Go binary, <15MB) that detects ungoverned AI before deployment. 8 detection categories across 3 scan tiers (basic/standard/full): unwrapped AI SDKs (CRITICAL), hardcoded endpoints, leaked credentials, missing dependencies, agent frameworks, MCP servers, AI infra, and unguarded prompts. Each organization picks the right tier for their maturity level. SARIF output for GitHub Security tab. Dedicated Scan Reports dashboard with findings trend charts and compliance report integration.

3 scan tiers 8 categories SARIF output GitHub Action Scan Reports UI Python/JS/Go/Java

Available as a GitHub Action (snapper/source-scan-action@v1) for one-line CI/CD integration with SARIF upload to GitHub Code Scanning.

Enterprise Features

SIEM Integration

Per-org SIEM targets with 4 transport types: Syslog (TLS), Webhook (HMAC-SHA256), Splunk HEC, and Azure Sentinel. CEF event format, secret redaction, and test connectivity.

MCP Integrity Verification

Tool manifest SHA-256 hashing with 8 suspicious-tool heuristics (credential harvester, prompt injection, encoded payload, and more). Per-org allowlists and risk scoring (0-100).

Plugin Integrity (Canary + Receipts)

Canary probes detect plugin removal/disabling (5-min heartbeat, alert after 3 misses). Evaluation receipts provide single-use proof that each tool call was evaluated, verifiable by downstream proxies.

Organization Policy

Organization-level security policies: MFA requirement, login lockout, session timeout, and audit retention. Admin-only access with audit-logged changes.

Organization Audit Log

Filtered audit trail scoped to your organization. Filter by severity, action type, date range, and text search. CSV export up to 10,000 records. Detail modal with full event context.

Meta-Admin Feature Flags

Per-org feature flag management UI. Toggle built-in flags (Slack, SSO, threat detection, browser extension), add custom flags, filter by plan. Platform admin only.

Cross-Org Audit

Platform-wide audit log for meta admins. Filter by organization, action type (26 types across 8 categories), severity, and date range. CSV export and detail modal.

Feed Health Monitoring

Redis-based health tracking for all security feeds (NVD, GitHub, ClawHub, MCP catalog). Staleness detection, auto-recovery of stale feeds, critical alerts on 3+ failures, and dashboard status card.

Performance Monitoring

Fleet health scoring (composite 0-100 per agent), evaluation latency breakdown (p50/p95/p99), 7-day activity heatmaps, denial hotspot tracking with trend analysis, and rule efficiency reports with dead/noisy classification. Auto-refreshes every 30s.

Air-Gapped Deployments

Full threat intelligence without internet. Curated CVE/advisory bundle (20 records), file import for custom intel, 4 deployment modes (cloud, private cloud, private server, air-gapped).

SOAR Integration

Bidirectional integration with 5 SOAR platforms: Splunk SOAR, Cortex XSOAR, Microsoft Sentinel, ServiceNow, and generic webhook. Snapper fires HMAC-signed incident events; your playbooks call back to block agents, create rules, or resolve approvals. Pre-built playbook library included.

GitHub Action (Marketplace)

One-line CI/CD integration via snapper/source-scan-action@v1 on the GitHub Actions marketplace. Runs the 3-tier source scanner on every PR, uploads SARIF results to GitHub Code Scanning, and blocks merges when ungoverned AI is detected.

Kernel Enforcement (Enterprise)

3-phase kernel roadmap: Phase 1 — Landlock/Seatbelt cage (shipped, 99 tests). Phase 2 — eBPF Sentinel: ring-buffer syscall/network/process monitoring, behavioral DNA, adaptive sandbox profiles that tighten over 14 days, Q-Learning escape detection. Phase 3 — TEE attestation via AMD SEV / Intel TDX. Self-learning kernel strategy links app-layer behavioral baselines to kernel enforcement for 6 cross-layer signal integration points.
